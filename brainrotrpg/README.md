# Brainrot RPG grimoire

Private campaign site, under development. This folder is isolated from the existing personal/company site. Its Worker config is separate. Root hardening changes are separate and remain undeployed.

Run `npm ci`, `npm test`, then `npm run preview`. Open `http://127.0.0.1:4173/?demo=1` for fictional design data. The local preview has no credentials or real campaign data. Production forbids demo mode.

## Access and storage

All deployed paths currently fail closed. The separate Registry pilot requires an exact hostname, explicit membership-grant ceiling and Registry binding before it can operate. Access JWT verification is an alternative code path, not the selected live route; no paid Access setup is enabled. Viewer assertions are verified against the issuer's RSA signing keys, signature, issuer, audience and expiry. Header email is never trusted. An additional scoped writer credential is retained only by the executing side, never given to the group or browser. No anonymous writes.

A single Durable Object serializes updates. PUT `/api/state` takes `{updateId, expectedVersion, snapshot}`. Unknown fields, routing/contact fields, invalid HP, duplicate IDs, bad roll math and unordered rolls reject. Versions advance atomically. An exact retry of a retained update returns its original saved receipt without reapplying; changed content under a reused ID and stale expected versions reject. Revisions are retained in the same transactional storage as current state. GET `/api/state` returns the saved state; `/api/export` and `/api/history/N` support verified backup and recovery. Recovery is a new versioned update using a verified old snapshot, never deletion of history.

The schema is provisional until the sanitized baseline adapter and group update contract are verified. No Doc polling, writing or mirror loop. Doc remains canonical until coordinated cutover. No automatic gameplay decisions, random rolls, derived unassigned bonuses or extra authority.

## Chat image API

No manual download button is on the website. Authenticated GET `/api/cards/CHAR-ID.svg?version=N` renders the saved character revision. The executing side fetches that protected endpoint and runs `node render-card.mjs input.svg output.png` to produce a real 1080x720 PNG for the group's existing attachment route. No credentials enter the renderer, front end or peer conversation. This SVG-to-PNG adapter is local execution, not a deployed public PNG endpoint. Event SVG endpoints are implemented but no historical real events exist. Live use requires approved canonical event records. API response and file delivery must be version-bound before any live use.

Private rendering tests use only explicit fictional sample state. `private/` is excluded from source packets and Git. Root candidate config uses an explicit ten-file public asset allowlist; root guard is defense in depth. Root changes are not live. The separate RPG Worker only serves approved presentation assets behind its own authorization.

Executor scope: WRITE_TOKEN is an executor-only full campaign read/write, export/history and enrollment/roster-admin credential. It deliberately bypasses viewer sessions; it is not claimed that every request requires a viewer JWT. It must never be put in the browser, API responses or group messages. Generated credential is stored in the vault; protected command use and installation are awaiting approval. The fixed-origin fetch helper still needs live qualification. Schema validation is NOT content sanitization. Only explicitly approved sanitized gameplay input may be sent by executor; free text can contain private information if the executor passes it.

Local access pilot limits: Registry remains unbound in deployment config. Browser credential lifetime is seven days, but every read requires a separate unexpired membership grant. The 24-hour test ceiling is not a production approval. Admin attestations require a source message ID and source timestamp, reject stale/out-of-order/replayed references, and are not identity verification by themselves. The trusted executor must recover the original group message and confirm who submitted their own browser's code. No current-roster API exists. Member revocation invalidates all their sessions; individual admin session revocation is not implemented (own logout is available). Anonymous issuance has a global 30/hour cap: this bounds storage but can deny enrollment to the whole group under attack. It is not a solved availability/DoS policy.

Local tests use Miniflare 5 beta, matching the installed Wrangler runtime generation, with an explicit module graph. This replaces vulnerable Miniflare 4 transitive dependencies; npm audit currently reports zero known vulnerabilities. Production Worker code has no npm runtime dependencies. Any deployment still needs independent review and live checks.

Protected executor route: `RPG_SECRET_FILE=/path/from/approved/vault/write-file node executor.mjs state` (or export, write FILE, member FILE, approve FILE, history REV, card ID REV OUTPUT, event ID REV OUTPUT). Fixed HTTPS origin only, redirects rejected, token never printed. Enrollment writes require original trusted-message evidence outside this helper; it is transport, not permission. Use a revision-bound SVG from this route with render-card.mjs to make a PNG. The helper has not been live-qualified yet. Delete vault-exported credential files after use.
